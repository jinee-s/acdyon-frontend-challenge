# DECISIONS.md

## 1. Why this implementation?

I chose Part 2 and built the homepage using plain HTML, CSS and JavaScript. The assignment only required a responsive product homepage, so I avoided unnecessary frameworks and dependencies. This allowed me to focus the available time on visual hierarchy, spacing, responsive behavior and a small amount of meaningful interaction.

I considered using a component framework, but for a single-page static experience the additional setup was not necessary.

## 2. Trade-off

Under the time limit, I prioritized the hero section, product preview, responsive layout and restrained motion over building a fully functional AI research backend.

I also avoided presenting fabricated product metrics, testimonials or customer logos. With a full week, I would connect the interface to a real research API and add loading, empty and error states, accessibility refinements, and richer product interactions.

## 3. AI tools

I used AI tools for brainstorming the product concept, generating initial implementation ideas and helping with debugging. I personally reviewed and simplified the implementation, verified the responsive behavior at mobile and desktop widths, and checked the final interactions before submission.

The final implementation was intentionally kept simple so that every major decision and piece of code could be explained during the follow-up interviw.
